# 25 — AI Content Package Architecture

**Version:** 1.0
**Last updated:** 2026-08-03

## 1. Vision & Constraints

The platform **must not** generate educational content internally using AI.
Instead, it acts as the consumer of a standardized, AI-generated educational package called the **QPack**.

Teachers prepare their content using external AI workflows (e.g., NotebookLM for knowledge extraction, Claude Desktop for assessment generation), and upload a single `lesson.qpack.json` file. The platform automates the entire ingestion process.

## 2. External AI Workflow (Outside the Platform)

### Step 1: Knowledge Extraction (NotebookLM or similar)
- **Input:** PDF, DOCX, PPTX, Teacher Notes.
- **Role:** Understand the source material deeply.
- **Output:** A structured Markdown file (`lesson.md`) containing:
  - Overview, Objectives, Prerequisites.
  - Key Concepts, Theory, Definitions.
  - Explanations, Common Mistakes, Best Practices, Edge Cases.
  - Bloom's Taxonomy Mapping, Skills, Metadata.

### Step 2: Assessment Generation (Claude Desktop or similar)
- **Input:** The `lesson.md` file from Step 1.
- **Role:** Generate a comprehensive educational package.
- **Output:** `lesson.qpack.json` containing:
  - Question Bank (MCQ, True/False, Matching, Ordering, Short Answer, Essay, Real-world Scenarios).
  - Exams, Quizzes, Homework.
  - Practical Assignments.
- **Question Metadata Requirements:** Each question must have a Unique ID, Difficulty, Topic, Lesson, Chapter, Tags, Skill, Bloom Level, Estimated Time, Marks, Correct Answer, Explanation, Hints, and Source Reference.

## 3. Platform Responsibilities (The Importer Engine)

The platform does not interface with NotebookLM, Claude, or any AI API. It strictly consumes the `lesson.qpack.json` file.

### 3.1. Automatic Validation
Before persisting data, the importer performs strict validation:
- **JSON Schema & Version:** Ensures compliance with the official QPack format.
- **Integrity Checks:** Detects duplicate IDs and duplicate questions.
- **Asset Checks:** Validates attachments, images, and code snippets.
- **Relational Checks:** Detects broken references between questions, lessons, and exams.

### 3.2. Automatic Import & Database Mapping
The system automatically creates and links the following entities within the database:
- **Course Hierarchy:** `Course` → `Chapter` → `Lesson`.
- **Content:** `Lesson Metadata`, `Attachments`, `Tags`, `Categories`.
- **Assessments:** `Question Bank`, `Homework`, `Quizzes`, `Exams`, `Practical Assignments`.
- **Taxonomies:** `Difficulty Mapping`, `Skills Mapping`.

### 3.3. Automatic Media Import
The platform extracts all binary/text assets bundled or referenced in the package:
- Images, PDFs, Markdown notes, attachments.
- These are uploaded to **Cloudflare R2** and linked back to the database entities.

### 3.4. Automatic Search Index
Content is immediately pushed to **Elasticsearch** to provide instant searchability across:
- Questions and Answers.
- Lesson theory and concepts.
- Keywords, Skills, and Tags.

### 3.5. Automatic Statistics Calculation
Upon import, the system calculates and stores package-level statistics:
- Total number of questions.
- Difficulty distribution (Easy, Medium, Hard).
- Question type breakdowns.
- Bloom's Taxonomy distribution.
- Estimated total solving time.
- Overall skills and lesson coverage.

### 3.6. Automatic Teacher Dashboard
Once the import completes, the Teacher UI instantly populates with:
- The imported Lesson tree.
- The populated Question Bank.
- Ready-to-publish Homework, Exams, and Quizzes.
- A visual Statistics Dashboard (charts showing Bloom distribution, etc.).
- A Validation Report detailing the import success.

## 4. Future Compatibility (Provider Independent)

The QPack JSON schema is the universal contract. 
- **Today:** Generated via NotebookLM + Claude Desktop.
- **Tomorrow:** Can be generated by Gemini, OpenAI, or custom autonomous agents.

The platform is completely agnostic to the AI provider. It only validates and parses the standardized `QPack` format.
